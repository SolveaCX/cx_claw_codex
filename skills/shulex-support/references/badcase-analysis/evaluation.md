# 批量诊断回归验收

修改本能力后，以固定输入和原始会话运行新指引，再独立核对结果。不要将旧报告结论作为标准答案；已有人审参考时说明依据及争议。第一次用代表样本，稳定后才扩到全量。

## 必验边界

| 场景 | 通过标准 |
|---|---|
| 同chatId两条不同投诉 | 两条独立定位；同一根因可以关联同一个修复项，但不丢行。 |
| 表头不同、合并单元格、已有分类下拉 | 输入可映射、合并语义有依据；输出始终固定10列和既定分类。 |
| 问题没进入Agent | agentId/agent名称留空；说明入口或前置断点，不借用其他轮Agent。 |
| 分类可确认但底层原因未查清 | 保留已证实类别，定位明确缺口；不把“待确认”放进分类。 |
| 错型号知识且正确知识未找到 | 不凭一次检索就判“缺知识”；不在K01和K02之间猜。 |
| 正常WAIT、合法提前交接 | 不误判节点异常；按规则核对实际应走分支。 |
| 已承诺交接但无交接事件 | 文案不作为TRANSFER证明；检查目标轮而非最终handoff。 |
| 工具HTTP错误 | 先核实工具断点，不凭语言或空回复就判分类错误/应回未回。12类覆盖不了可留空。 |
| 原表“已优化”或当前流程已改 | 历史错误与当前状态分开，没有回归不标已验证通过。 |
| 非问题与证据不足 | 前者有依据可无需处理，后者保留缺口，不能混淆。 |
| 查询失败或歧义ID | 保留任务行和原ID，不随意选候选；不阻塞其他case。 |
| HTML/XLSX一致性 | 数量、分类、Agent、处理方式、case/fix引用一致，表头及ID类型正确。 |
| 工作台导航与case对话 | 总览可下钻、菜单切换视图、分类与Agent筛选可组合；进入case看真实对话与诊断，返回保留筛选；同chatId不同问题分别定位正确消息。 |
| 会话展示的真实性与离线使用 | 正确区分客户、AI、人工及内部记录；缺失原文不补写、部分记录有说明；脱敏后保留判断依据，消息内容不执行，离线可读且无临时路径依赖。 |
| 多worker请求同一配置 | 同资源快照仅一个获取负责人；其他worker复用可用结果，失败不被当成空配置。 |
| 同Agent跨版本、草稿与发布版 | 快照分开，case引用实际使用的版本；未取得历史图时明确证据缺口。 |
| 任务中断、压缩与重新分配 | 已验收结果不重跑，不丢未完成case；原worker结束后再重派，缓存文件缺失时重新取证。 |
| 不同本地目录与无并行能力 | 使用实际可访问路径，不依赖固定目录；顺序降级仍满足逐条证据与相同输出契约。 |
| 二级空白且已确认不适用信息收集 | 区分分类未覆盖与证据不足；前者提供有依据的模型建议，正式10列和既定分类不变，HTML单列建议分布。 |
| 交付阅读定位和修复建议 | 正文能说明客户遇到什么及怎么改；节点用真实名称，名称来源可追溯；原始状态和长ID可在技术证据中查到。 |
| case回归 | 建议包含原case的复测输入、必要上下文和预期结果；共享配置改动覆盖同因case及相关正常场景。 |
| 历史版本与当前版本不同 | 按目标轮版本请求历史图，不因最新图不同直接结束补证；版本缺失或返回不匹配不能回退成当前图。 |

## 评估记录

每轮记录：输入快照、skill分支/提交、样本范围、实际取证时间、覆盖类别、分类与根因确认数量、方案就绪数量、待补证、人工复核差异。样本回放通过不等于新对话独立调用或全量稳定；区分流程回放、宿主真实调用、修复后业务回归三种验证。

并行评估还记录worker数量、批大小、总耗时、资源实际查询次数、缓存命中与重复请求、失败重试、重派和结果缺失。用同一输入及可比快照对比顺序/并行的分类、证据完整度和耗时；配置已变时单独说明，不能把变化误算为提效。验收前核对宿主实际加载的skill及新增references与源码一致，不能只检查同步目录或版本号。

原始客户数据和试跑产物放用户指定交付目录/临时目录，不纳入插件源码。最终交付仍只有HTML与XLSX；本回归规范是维护文档，不额外产生用户报告文件。
