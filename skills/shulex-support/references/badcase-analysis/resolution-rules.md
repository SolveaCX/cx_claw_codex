# badcase 分类与推荐解决路径

分类必须来自排查证据。每条结论必须使用 `问题分类：<分类名称>` 明确展示主分类，不能只写现象、模块或根因。证据不足时使用 `问题分类：待确认`；明确属于代码、服务或运行时问题时使用 `问题分类：需产研`。先给推荐解决路径，再补充当前 case 的具体修改对象、修改内容和复测方式。

| 问题分类 | 推荐解决路径 |
|---|---|
| 主意图识别错误 | 修改主意图的意图描述。 |
| 问题分类器识别错误 | 修改对应问题分类器的描述。 |
| 回复模板错误 | 修改回复模板。 |
| 知识回复错误（有知识调不到转人工） | 1. 检查知识回复节点是否选择对应文件夹；缺少则补充文件夹并复测。2. 文件夹正确但客户问题与知识描述相关性不足时，优化知识描述并复测。3. 两项均正常时转产研排查。 |
| 知识回复错误（有知识调用到不相关知识） | 1. 找到正确知识及其文件夹。2. 检查对应节点是否调用该文件夹；未调用则新增并复测。3. 已调用时对比客户问题与正确知识描述的相关性；相关性不足则优化知识描述并复测，相关性高则转产研排查。 |
| 知识本身错误 | 找到错误知识，修改知识并复测。 |
| 知识回复错误（无知识但调用到不相关知识） | 1. 找到误调用知识及其文件夹。2. 检查节点是否应该调用该文件夹；不应该则移除并复测。3. 应该调用时新增正确知识并复测；仍未解决则转产研排查。 |
| 重复索要已提供的信息 | 排查订单号、图片等信息的提取或状态传递，再优化“信息收集”Prompt，明确不得重复收集已提供信息。 |
| 重复排故（知识召回正确，但是客户已按知识库排故，需要剔除已排故步骤） | 优化“排故”步骤的 Prompt，明确不得重复提供客户已完成的排故步骤。 |
| 不按提示词执行 | 找到错误节点，优化 Prompt 并复测。 |
| 订单号/名字等变量提取错误/失败 | 优化对应变量的提取 Prompt 并复测。 |

## 判断边界

- “转人工”是结果，不是根因；必须继续确认意图、分类器、流程、知识、模板、变量或运行时中的实际原因。
- 同一 case 同时涉及多个模块时，选择最上游且能解释最终错误的原因作为主分类。
- 当前配置与历史执行不一致时，分别标记“当前状态”和“历史事实”，不能用当前配置替代历史根因。
- 推荐解决路径中的“修改”只表示建议动作；用户选择修复项前不得执行写操作。
- 需要转产研时，整理会话标识、目标轮次、已确认事实、trace / armsTrace、当前配置和缺失证据。

## 修复能力路由

| 修改对象 | 路由 |
|---|---|
| 主意图、策略、变量系统 | `solvea-kit` |
| 问题分类器、ChatFlow 节点、Prompt、流程变量 | `agent-builder` |
| 回复模板、知识、知识文件夹 | `kb-builder` |
| 修复后单条或批量复测 | `agent-tester` |
| 代码、服务、运行时或证据不足的问题 | 整理产研跟进材料；用户需要售后跟进时进入工单流程 |
