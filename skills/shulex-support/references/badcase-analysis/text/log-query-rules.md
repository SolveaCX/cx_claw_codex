# 日志查询约束

统一证据收集阶段调用 `$HOME/.codex/cxclaw/bin/cxclaw-launcher sls query` 时必须遵守以下规则，避免无节制地查日志。

## 硬上限

- **单轮诊断最多 20 次 SLS 查询**（含 Step 1 定位 trace 的查询）
- 达到上限即停止查询，在报告中写明：「当前日志层面已分析到位，建议联系研发团队进一步排查。」

## 连续空结果止损

- 连续 3 次查询返回 `count=0` → **停止继续扩词或换关键字**
- 优先自查：
  1. trace 是否定位到了？Step 1 的 `rest:"<chatId>"` 和入口路径是否写对？
  2. query DSL 字段名是否拼错（`rest` / `trace` / `severity`）？
  3. 时间窗是否包含了会话记录的 `createdAt`？
- 若三项自查后仍无结果，停止继续查日志，用已收集到的会话记录、配置和手册证据出报告，并说明日志未能确认。

## 查询策略

- **必须先定位 trace 再查模块日志**：不允许无 trace 的全库检索。
- 模块日志严格按会话记录、配置和模块手册信号选择，不要批量拉所有模块。
- 同一模块先用 `"line": 20`，定位到关键行再决定是否扩量；禁止一次请求 `"line": 500`。

## DSL 写法规范

- 字段名不带引号：`rest` / `trace` / `severity` / `ext_2` 等
- 字符串值必须加双引号：`rest:"HTTP_ASPECT"`（不是 `rest:HTTP_ASPECT`）
- 关键字大写：`AND` / `OR` / `NOT`
- 多条件用括号分组：`trace:"xxx" AND (rest:"A" OR rest:"B")`

## 时间窗

- 应用日志保留一个月；带上 trace 后时间窗放宽到 ±30min 甚至更宽都安全
- 默认先用 `createdAt ± 5~10min`，漏查再扩到 ±30min
- **禁止反复拉取相同 trace + 相同 query + 相同时间窗**，这是浪费配额
