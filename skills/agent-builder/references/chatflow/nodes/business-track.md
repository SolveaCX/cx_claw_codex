# BUSINESS_TRACK

## 功能概述

发送一个或多个业务追踪事件，不向客户回复、不等待输入，也不改变业务判断。执行完成后沿唯一 `SOURCE`
出边继续。适合在已确认的业务里程碑记录分析/归因事件；不要用它代替 TOOL、条件判断或用户可见回复。

## 创建方式

```json
{
  "key": "track_order_lookup",
  "type": "business_track",
  "trace_events": ["order_lookup_started", "after_sales_flow"]
}
```

## 创建参数

| 字段 | 说明 |
|------|------|
| trace_events | 非空业务事件编码数组；每一项必须是非空字符串 |

## Edges

仅 `SOURCE` 单出边。通常把它放在需要记录的业务动作之前或之后，并明确记录事件对应的阶段。

## Resource Dependencies

事件编码应来自已确认的业务埋点口径；不因名称相似臆造新的编码。

## 限制

- 必须有入边和 `SOURCE` 出边。
- 不发送客户消息，也不等待客户输入。
- 不携带变量 selector；事件码是静态业务配置。
- 不用它作为“看起来有动作”的占位节点；没有确认的追踪需求时不新增。

## Common Mistakes

- 把用户回复、工具调用或状态判断塞进追踪节点。
- 只写空数组或空事件字符串。
- 将追踪节点作为终点，导致后续业务处理断开。
